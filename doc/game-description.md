# Void Runner 3D Game Description

## Meaningful Summary
Void Runner 3D is a polished browser-based 3D arcade survival game with a transparent blockchain-backed competitive layer. At its core, it is a fast sci-fi dodge game: the player pilots a spaceship through an increasingly hostile asteroid field, survives as long as possible, collects power-ups, and converts skilled defensive play into bonus score. Around that gameplay loop, the project adds public handle registration, player-owned score records, chain-backed leaderboards, and deterministic block-derived round and leg status through the systems described in [`README.md`](../README.md), [`index.html`](../index.html), [`leaderboard-relay.js`](../leaderboard-relay.js), and [`CHANGELOG.md`](../CHANGELOG.md).

## Comprehensive Detailed and Versatile Description of the Game

Void Runner 3D is a no-install 3D HTML5 space survival game set in a hostile deep-space corridor where the player must guide a compact futuristic ship through dense incoming debris and survive for as long as possible. The game is designed as a self-contained browser experience, with the entire shipped client living in [`index.html`](../index.html), making it lightweight to distribute and immediate to launch while still delivering a visually rich arcade presentation through Three.js rendering, particle effects, procedural audio, and a full gameplay HUD.

The central fantasy of the game is simple and strong: you are a lone pilot running the void, threading through an asteroid storm that becomes more aggressive the longer you stay alive. Asteroids spawn ahead of the player and accelerate into the play space, forcing constant micro-adjustments, anticipation, and spatial awareness. The ship moves within a bounded arena, giving players enough freedom to improvise while keeping every mistake meaningful. The result is a skill-first gameplay loop that is easy to understand immediately and difficult to master over repeated runs, as seen in the difficulty and world configuration at [`index.html`](../index.html:666) and [`index.html`](../index.html:672), plus the asteroid logic in [`updateAsteroids()`](../index.html:2245).

The controls are deliberately flexible so the game can feel natural across devices and play styles. Players can steer with keyboard inputs using arrow keys or WASD, use optional mouse guidance, and interact through touch on supported devices. This makes the game accessible as both a desktop score chaser and a mobile-friendly browser experience, with input routing handled in [`getInputDirection()`](../index.html:2157) and [`bindInput()`](../index.html:2508). The game also supports pausing manually and auto-pauses on focus loss, helping preserve fairness and keeping timing tied to actual active play rather than background tab time.

Void Runner 3D uses a layered score model that gives the game more depth than pure survival. A run’s total score is not only the raw time spent alive but the sum of survival time and bonus time. This bonus time comes from the salvage mechanic: when the player has an active shield and absorbs an asteroid hit, the shield prevents death and activates a temporary salvage multiplier window. During that window, extra bonus score accumulates over time. Repeated shielded collisions refresh the window and increase the multiplier until a cap is reached, turning skilled timing and aggressive risk management into an advanced scoring strategy. This makes the game appealing both to casual players who simply want to survive and to advanced players who want to optimize routes and shield usage for leaderboard performance. The score formula and salvage behavior are implemented in [`getCurrentRunScore()`](../index.html:1868), [`activateSalvageMultiplier()`](../index.html:1882), [`updateSalvageAndBonus()`](../index.html:1892), and are explicitly validated in [`game.test.js`](../game.test.js:353).

The power-up system reinforces this layered design. Two power-ups define the moment-to-moment tactical choices: Shield and Boost. Shield provides temporary protection and can nullify an otherwise fatal asteroid collision, while also enabling the salvage system that can convert danger into score. Boost increases ship speed for a short duration, changing the handling profile and allowing faster repositioning. Their durations and visual feedback are managed by [`applyPowerup()`](../index.html:2107) and [`updatePowerup()`](../index.html:2134), while spawning and pickup behavior are handled in [`spawnPowerup()`](../index.html:1939) and [`updatePowerups()`](../index.html:2299). These systems give runs variation without overwhelming the player with complexity.

Difficulty selection broadens the game’s range and replay value. Easy, Normal, and Hard each adjust asteroid spawn rate, scaling curve, and speed multiplier, creating distinct play profiles for beginners, regular players, and high-skill competitors. Normal is the default and also functions as the featured competitive difficulty in the shipped release model, as documented in [`README.md`](../README.md:18) and exposed in the UI at [`index.html`](../index.html:581). This means the game can be positioned as a casual survival challenge, a hardcore score attack game, or a competitive featured ladder depending on the audience.

Presentation is one of the game’s strongest descriptive angles. Void Runner 3D combines retro-arcade readability with modern sci-fi atmosphere. The ship is fully modeled in-scene rather than represented as a flat sprite, the background is filled with a dense starfield, lighting includes ambient, directional, and hemisphere sources, and collisions generate bursts of particles, camera shake, explosion noise, and ship fragmentation. Game-over events slow time briefly, increasing drama and giving each crash a cinematic punch. These features come from the scene and effects systems in [`index.html`](../index.html:761), [`index.html`](../index.html:873), [`index.html`](../index.html:955), and [`triggerGameOver()`](../index.html:2341). Audio is also generated procedurally through the Web Audio API rather than external files, with separate sounds for engine hum, pickups, impacts, explosions, and near-miss whooshes through functions such as [`initAudio()`](../index.html:1069), [`playPowerupSound()`](../index.html:1111), [`playExplosionSound()`](../index.html:1128), and [`playWhooshSound()`](../index.html:1155).

From a UX perspective, the game is carefully split between active-play clarity and meta-level information. During a run, the HUD only shows the essentials: current difficulty, current run timer, local best, active salvage status, and active power-up duration. This keeps the screen focused and avoids distracting the player from navigation. That active HUD is defined at [`index.html`](../index.html:565) and described in [`README.md`](../README.md:113). More complex information appears only in the menu and game-over overlays, preserving the purity of the arcade loop.

What makes Void Runner 3D especially distinctive is its competitive backend. The game is not only a local score chaser; it also supports a blockchain-backed public competition model through [`leaderboard-relay.js`](../leaderboard-relay.js). Players can choose a handle, register it, and then submit scores into their own player-owned record rather than into a generic centralized leaderboard row. This identity and ownership model is described in [`README.md`](../README.md:31), with browser-side registration and submission handled in [`registerPlayerForChain()`](../index.html:1747), [`submitScoreToChain()`](../index.html:1808), and player-state application through [`applyPlayerStatus()`](../index.html:1512). That structure makes the competitive layer feel less like a hidden service and more like a transparent extension of the game world.

The relay exposes public APIs for health, leaderboard reads, player status, registration, score submission, featured rank context, and release-economy views, as documented in [`README.md`](../README.md:46). In practical terms, this means the menu can show a live chain leaderboard for the selected difficulty, while the game-over screen can show top-five featured-chart context, the player’s featured placement, and delta-to-leader information. Those UI pieces appear in [`index.html`](../index.html:606) and [`index.html`](../index.html:630), with supporting logic in [`loadChainLeaderboard()`](../index.html:1682) and [`loadFeaturedRankContext()`](../index.html:1657). This gives the game a strong social and competitive framing without making the basic offline-style play dependent on that infrastructure.

In the shipped `v0.1.0` release, the larger competition model is expressed as a deterministic release economy derived from blockchain block height rather than wall-clock timers or manual admin control. The game surfaces current round, current leg, countdowns, eligibility status, reward distribution summary, recent settled rounds, outcome status, player obligations, and leg reset timing through relay-backed reads. This model is documented in [`README.md`](../README.md:10) and the release design reference [`doc/release-plan.md`](./release-plan.md:1). For description purposes, this means Void Runner 3D can credibly be presented as a transparent competitive web game where standings and settlement state are derived from chain-visible data rather than opaque hidden server rules.

The reward structure is one of the most important parts of that competitive framing, and it deserves to be described clearly because it shapes how players interpret success, risk, and participation. In the featured release flow, rounds are evaluated on a deterministic basis and, when enough qualified participants are present, the round produces a top-four reward tier and a bottom-six liability tier. The top four players receive fixed ROD payouts of 100, 70, 20, and 10 respectively, as documented in [`README.md`](../README.md:25) and recorded in [`CHANGELOG.md`](../CHANGELOG.md:8). This means first place is treated as a major competitive victory, second place remains highly valuable, and third and fourth still receive meaningful public reward recognition. The reward ladder is therefore not flat: it strongly emphasizes elite placement while still preserving incentive for players who may not realistically expect to win every round.

Just as importantly, the model is not a simple winner-takes-all prize system. The bottom six positions in a qualified settled round carry fixed liabilities of 28, 30, 33, 35, 36, and 38 ROD, matching the deterministic schedule described in [`README.md`](../README.md:27) and [`doc/release-plan.md`](./release-plan.md:45). This creates a competitive economy where placement has consequences across the whole top ten, not only at the very top. Players are not just racing for rewards; they are also trying to avoid landing in the liability band. That makes every rank meaningful, especially near the midline where the difference between barely entering the reward zone and slipping into the obligation zone can materially change the outcome of a round.

This reward-and-liability design gives Void Runner 3D a distinctive tension. High placement offers visible upside, but weak placement in a qualified round can create an outstanding obligation that the player must settle. If obligations remain unpaid, the player can be blocked from reward participation until the end of the current leg, as outlined in [`doc/release-plan.md`](./release-plan.md:54) and reflected in the player-facing eligibility and obligations UI loaded by [`loadReleaseOverview()`](../index.html:1376) and [`loadGameOverReleaseSummary()`](../index.html:1434). In other words, the reward system is not only about payout; it is also about accountability, visibility, and ongoing competitive status.

From a descriptive standpoint, this makes the reward model much richer than a typical web leaderboard. Rewards in Void Runner 3D are deterministic, publicly interpretable, placement-sensitive, and tightly connected to player eligibility. The system encourages repeated play by giving players multiple goals at once: reach the reward tier, avoid the liability tier, protect eligibility for future rounds, and monitor current standing inside the leg. Because the menu and game-over overlays surface current reward distribution, obligations, and settlement context in [`index.html`](../index.html:588) and [`index.html`](../index.html:620), players are not left guessing about what the rewards mean. The game actively presents the competitive stakes as part of the broader experience.

Another important part of the project’s identity is trust and integrity. The shipped runtime includes integrity verification for both the browser client and the relay binary, with startup checks comparing hashes against expected on-chain values and enforcing read-only behavior under integrity warnings. This is described in [`README.md`](../README.md:69) and [`CHANGELOG.md`](../CHANGELOG.md:5). That gives the project a strong anti-tamper narrative for technical or blockchain-oriented audiences.

Taken together, Void Runner 3D is a versatile game to describe because it operates successfully on multiple levels at once. It is a stylish 3D arcade survival game. It is a fast score-attack challenge with layered mechanics. It is a browser-native sci-fi experience with clean replay loops and immediate accessibility. And it is a transparent competitive platform where identity, score ownership, standings, and reward/liability views are tied to a public relay and deterministic chain-derived state. Those qualities are consistently reflected across [`README.md`](../README.md), [`CHANGELOG.md`](../CHANGELOG.md), [`index.html`](../index.html), and [`game.test.js`](../game.test.js).

### 4. Technical/product version
Void Runner 3D is a single-file web game implemented in [`index.html`](../index.html) with inline HTML, CSS, and JavaScript, using Three.js for rendering and the Web Audio API for procedural sound. Its runtime combines state-machine-driven arcade gameplay, difficulty-scaled obstacle spawning, power-up handling, pause-safe timing, local score persistence, and a composite scoring model. The game is extended by [`leaderboard-relay.js`](../leaderboard-relay.js), which provides authoritative public APIs for player identity, score submission, leaderboard reconstruction, integrity enforcement, and chain-derived release-economy views. That release economy includes deterministic settlement tiers in which the top four qualified ranks receive fixed ROD awards and the bottom six receive fixed liability amounts according to the schedule documented in [`README.md`](../README.md:25) and [`README.md`](../README.md:27).
